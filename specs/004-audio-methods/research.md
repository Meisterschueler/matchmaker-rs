# Research: Remaining Audio Methods and Features

**Date**: 2026-11-03
**Reference**: Released pymatchmaker 0.4.0 in tools/golden/.venv/Lib/site-packages/matchmaker; environment pinned by tools/golden/uv.lock.
**Evidence**: The initial sections record read-only research. The dated implementation entries below contain the later fixture, numerical, benchmark, and gate evidence.

## R1 - Incremental delivery

- **Decision**: One story per coherent commit, ordered C01-C12; goldens, facades, exports, docs, benchmarks, and gates belong to that commit.
- **Rationale**: Existing audio infrastructure is already implemented; an infrastructure megacommit or simultaneous new algorithms would violate the user's delivery constraint.
- **Alternatives considered**: Parallel method ports, separate core/facade commits, and a generic registry are rejected. Test-first edits within a story are allowed; unfinished algorithm commits are not.

## R2 - Tempo-aware Arzt and multiple unfolding hypotheses

- **Decision**: Reuse ArztFrame; port ArztTempoModel into utils/tempo_models.rs, expose arzt_tempo in its own method module. Port the multi-fold selection owner into dp/arzt_multi_fold.rs and use existing score repeat/unfold structures.
- **Rationale**: methods.yaml maps arzt_tempo to OnlineTimeWarpingArztFrame plus ArztTempoModel. dp/oltw_arzt.py contains before_step, tempo-dependent advance, reset, and state-history behavior; utils/tempo_models.py owns the tempo model. dp/oltw_arzt_multi_fold.py owns selection_window=50 and switch_margin=0.05.
- **Alternatives considered**: Duplicating ArztFrame or treating multi-fold as merely a different pre-unfolded score loses the controlling reference behavior.
- **Gate**: US1 captures tempo insertion/deletion/history state; US2 captures candidate unfolding, score-position domain, switching, and ties before changing the shared follower.

## R3 - Existing evaluation, no second evaluator

- **Decision**: Reuse src/utils/eval.rs and GroundTruth. Extend the audio follow branch that currently rejects --ground-truth; support direct perf_sec/score_beat TSV without asking the MIDI loader to read audio.
- **Rationale**: CLI already has follow/eval and the exact reference mapping primitives. The reference definition is utils/eval.py:evaluate_alignment, not the paper's alternative interpretation.
- **Alternatives considered**: A new audio accuracy formula is rejected. MIDI-note match files require a separately supplied MIDI performance and are not inferred from audio.

## R4 - FFT-based processor reuse

- **Decision**: Reuse realfft and nearby chroma/LSE conventions for raw spectrum, mel, MFCC, and Korzeniowski features; share small helpers only when actual duplication appears.
- **Rationale**: features/audio.py specifies center=False for raw spectrum, mel, and MFCC; mel/MFCC use n_fft=2*hop. Defaults are N_MELS=128, N_MFCC=13, NORM=np.inf; MFCC norm="backward" is passed to librosa and must be checked in the locked environment rather than silently replaced by "ortho".
- **Alternatives considered**: A new DSP dependency for a short FFT-bank/DCT computation is not justified. A maintained DCT dependency is evaluated only if its implementation meaningfully reduces complexity and matches scipy's scaling.
- **Gate**: If the released MFCC configuration fails in the locked environment, report a reference compatibility blocker; do not invent successful default goldens.

## R5 - Constant-Q parity and state

- **Decision**: CQT must reproduce the locked librosa transform, including filter norm, resampling, padding, complex magnitude, and trimmed edge frames. Evaluate maintained pure-Rust alternatives in US6 before writing kernels; use installed realfft/rubato only if the candidate evaluation justifies a targeted port.
- **Rationale**: CQTProcessor returns abs(cqt).T.astype(float32)[1:-1] over 88 bins from A0, norm=np.inf. CQTSpectralFluxProcessor also trims [1:-1]; its default 89th bin is half-wave flux. It compares the full current CQT matrix to the previous call's matrix, not simply adjacent rows within the call; the initial call's flux is zero. The class has no reset override; Processor.reset is a no-op. Do not assume the score-to-performance reset clears its matrix.
- **Alternatives considered**: No parity-compatible maintained CQT crate was verified during this planning pass. An approximate log filter bank, a C-backed backend, and Python/FFI in the default runtime are rejected. Absence of a verified crate is not proof that no crate exists.
- **Gate**: Compare a small pure-Rust prototype against fixed librosa inputs at default and overridden hops/rates. Record candidate version/license/MSRV/WASM status and max deviations before US6 registration. A failed probe pauses C06 and the sequence. US7 also probes full score-to-performance matrix shapes and inherited no-op reset; a failing released pipeline is a reference blocker, not permission to silently change flux/reset semantics. Use fresh instances for independent runs.
- **Outcome (C06)**: no maintained pure-Rust crate reproduces the locked transform; `cqt` is a targeted `f64` port with a fitted decimator and a per-frame limit, see R13.

## R6 - SKF spectral templates

- **Decision**: Port the reference's synthesized templates and Gaussian-peak fallback as distinct, recorded modes; reuse RustySynth for runtime synthesis, FluidSynth only for reference generation.
- **Rationale**: prob/skf.py:build_spectral_templates first attempts synthesized chord spectra and otherwise uses harmonic Gaussian templates. SKF consumes raw magnitudes (257 default bins) with sample_rate=8000, hop=128, n_fft=512. Synthesis differences cannot be hidden as state-recurrence errors.
- **Alternatives considered**: Using Gaussian mode permanently or catching every error as permission to switch modes would change the reference's successful path. User asset/config failures remain typed errors, not fallback triggers.
- **Gate**: Pin the reference SoundFont and template mode; compare replay using identical templates, then full-pipeline metrics. Only reproduce a fallback condition observed and documented in the reference.

## R7 - Audio outer-product HMM templates

- **Decision**: Keep audio outerhmm distinct from MIDI OuterProductHmm. Port weighted sustained-note chord templates, the two-layer sound/pause state, and the pitch-template overlay rule.
- **Rationale**: prob/outer_product_hmm_audio.py:build_pitch_cqt_templates synthesizes all 88 MIDI pitches 21-108 (velocities 50/80/110), then overlays rows from templates/pitch_templates_{sample_rate}_{hop}.npz where the learned row sum exceeds 0.5. Default facade hop is 640 at 16000 Hz / 25 fps; a corresponding bundled archive exists. This is a synthesis-plus-overlay model, not an interchangeable synthesized-only fallback.
- **Alternatives considered**: Reusing MIDI emissions, silently omitting learned rows, or replacing the template SoundFont without metric evidence are rejected.
- **Gate**: US8 audits exact asset origin, license, hash, dimensions, and support mask before copying/redistributing anything. Archive license was not established in planning. Compare fixed-template replay separately from rendering. methods.yaml does not forward sample_rate into the follower constructor; US8 must capture override behavior rather than silently repair that upstream quirk.

## R8 - Structured observations and score model

- **Decision**: Keep existing vector Observation unchanged. US11 adds KorzeniowskiObservation and a dedicated processor with its own typed output; US12 adds the score model and a direct consumer path. Standalone extraction exports the structured fields separately.
- **Rationale**: features/processor.py defines spectrum, active_notes, onset, onset_notes, loudness; audio sets the two note fields to None. audio.py uses periodic Hann, L2-normalized rFFT magnitude, positive flux of unnormalized spectra divided by current sum+1e-8, and librosa RMS/amplitude_to_db. The onset is not clamped to [0,1]. The score processor builds beat_grid, onset_positions, nearest_onsets, rest_mask, templates, and active_notes analytically; it does not require FluidSynth or learned assets.
- **Alternatives considered**: Flattening onset/loudness into an undocumented Vec<f32> would weaken the observation contract; changing every existing vector caller for one structured processor adds unnecessary blast radius.
- **Gate**: Preserve reference frame cropping/padding and silence dB floor. Default direct processor hop is 512, but the Matchmaker pfkorz facade derives hop=1470 from 44100/30 unless overridden; test both entry points.

## R9 - Seeded particle filtering

- **Decision**: Expose an explicit seed with default 1984, use a maintained deterministic seeded Rust RNG, and validate Rust repeatability plus reference accuracy across seeds 1984-1988. Do not require NumPy-identical random streams.
- **Rationale**: prob/particle_filter_korzeniowski.py has a per-instance RandomState(1984); the registry facade defaults num_particles=500 whereas a raw constructor/provider can have a different default. Constitution I permits metric comparison for stochastic methods; IV requires selectable seeds and repeatability.
- **Alternatives considered**: Global mutable RNG, unseeded platform entropy, or claiming exact posterior parity between distinct generators are rejected.
- **Gate**: US12 evaluates RNG license/MSRV/WASM portability and replay checks for deterministic suboperations (weights, normalization, resampling with fixed draws). Reference seed-set generation can override its RNG in the fixture harness without modifying the pinned package or release.

## R10 - Verification policy

- **Decision**: Use the explicit comparison limits in contracts/audio-api.md. Establish reference fixtures and first-difference reporting before porting each slice; limits are not adjusted merely to make a port pass.
- **Rationale**: Full-pipeline synthesis and random-stream differences need the exact evaluator; deterministic feature/state comparisons still require their own goldens. Existing benchmark infrastructure already supports feature/inference timing and five-run reports.
- **Alternatives considered**: A single end-to-end tolerance hides the root stage. Automatically relaxing limits, skipping inconvenient platforms, or marking unrun gates complete is rejected.

## R11 - Score audio conventions (level and framing)

- **Decision**: Follow the pinned reference in the two implicit conventions that fix the *absolute* values of score features: (1) the rendered score is peak-normalized to 1.0 before padding and cropping; (2) score features come from one whole-signal `center=False` pass (frame `j` at sample `j*hop`, chroma tuning estimated once over the score, no stream priming). Each is one private function with one call site in `src/score/audio.rs` (`normalize_level`, `extract_score_features`) and applies to every audio method and processor, so a different convention is a local replacement.
- **Rationale**: pymatchmaker calls `partitura.save_wav_fluidsynth`, whose `synthesize_fluidsynth` divides the piece by its peak (a side effect inside a dependency, invisible in the matchmaker sources), and builds score features with a single `processor((score_audio, 0.0))` call (`registry._reference_score_audio`). Chroma and LSE normalize every frame and hid both; `raw_spectrum` and the later unnormalized processors do not. Measured against the pinned reference: raw RustySynth peak 0.145 versus 1.0 (about -17 dB in every octave band, waveform correlation 0.9998, lag 0); score-feature error 0.855 before and 0.014 after removing the gain; Rust's stream framing shifts `raw_spectrum` score frames by two and adds two (2618 versus 2615 frames), which coincides with the reference only for `n_fft == 2*hop`. The unmodified reference fed with the raw Rust waveform fails exactly like Rust (the follower port was never at fault); with peak normalization and whole-signal framing it recovers its baseline.
- **Alternatives considered**: (A) both fixes only for `raw_spectrum`: smallest diff, but a per-processor special case for a renderer property, repeated for SKF/CQT/mel/MFCC. (C) normalize for all, whole-signal framing only for `raw_spectrum`: keeps a second framing path and the per-frame chroma tuning. (D) ship `raw_spectrum` as standalone extraction only: needs a spec change and leaves both defects for C05-C12. (E) normalize only and relax the gate: Rust's stream framing is even closer to the notes than the reference (median error 0.006 versus 0.017 beat) but is not reference-faithful (two frames apart, median difference 0.0116 > 0.01). Rejected outright: a constant gain (the reference normalizes per piece, so it breaks on other scores) and per-frame normalization of `raw_spectrum` (changes the reference algorithm and the verified extraction).
- **Limits and known deviations**: Partitura divides by the peak of the *last* (track, channel) signal and Rust renders one mix, so multi-track scores are unverified (all fixtures are single-track, `(0, 0)`). A silent piece stays unchanged where the reference would produce NaN. A score shorter than one analysis window is an `AudioConfig` error (the reference's `librosa.stft` raises there, too). The *performance* level is not normalized, neither is it in the reference, so level-sensitive features stay as fragile against recording level as there (a FluidSynth score scaled by 0.25 or less fails in the reference, 0.5 to 2 works, 4 fails again).
- **How to replace**: edit `normalize_level` and/or `extract_score_features` only (their contracts are in the doc comments and in contracts/audio-api.md, "Score audio conventions"), update `tests/score_audio.rs`, then re-run the audio golden tests and the audio benchmark (`tools/bench/audio.toml` for Rust and `tools/bench/run_reference.py`); the report's parity against the pinned reference decides.

## R12 - SKF template mode and synthesis rate

- **Decision**: `skf` has two explicit template modes, `synthesized` (default) and `gaussian`, recorded in every export (`score/meta.json`, `skf/meta.json`); there is no silent fallback. Synthesized templates follow the reference recipe (120 BPM, 0.3 s chords with 0.1 s gaps, velocity 100, Hann-windowed magnitude spectra averaged from 20 ms after the onset, floor `1e-10`, rows normalized to sum 1) but RustySynth renders them at the smallest integer multiple of the follower's sample rate that is at least 16 kHz (its minimum; 8 kHz becomes 16 kHz), analyses them with an FFT that is that many times larger (analysis hop 128 scaled the same way) and keeps the lowest `n_fft / 2 + 1` bins. This is one function, `synthesize_templates` in `src/prob/skf.rs`, with one call site.
- **Rationale**: The reference's `build_spectral_templates` calls `partitura.save_wav_fluidsynth` without a SoundFont (Partitura's bundled MuseScore General) and falls back to Gaussian peaks on any exception, printing only to stdout. In the locked environment and in CI that asset is an empty placeholder, so the unpatched reference silently runs Gaussian templates. The mode decides the quality: on the bundled piece (`tests/golden/audio/ground_truth/ground_truth.tsv`) the reference with the pinned SF2 reaches median error 0.0363 beat and 0.75 accuracy at 0.1 beat, its Gaussian fallback 0.625 beat and 0.25. The benchmark reference therefore pins the mode by patching `partitura.save_wav_fluidsynth` with the SF2 (as for score audio) and the generator refuses a golden whose reference did not synthesize. The doubled-FFT analysis reproduces the reference's native 8 kHz analysis: cosine similarity of the templates 0.9957 minimum and 0.9999 median, and the reference follower's path differs by more than 0.05 beat in 0.2 % of the frames. RustySynth against FluidSynth at 16 kHz: cosine 0.9997 minimum; against FluidSynth at 8 kHz: 0.9959 minimum, total variation 0.039 at most; the reference follower fed with the Rust templates has median error 0.0367 versus 0.0363 beat, accuracy 0.750 versus 0.750 and p95 0.371 versus 0.374, with 0.4 % of the frames more than 0.05 beat apart.
- **Alternatives considered**: (A) render at 16 kHz and resample to 8 kHz before the 512-point analysis: needs a resampler choice and reproduces neither the reference's aliasing nor an ideal analysis. (B) Gaussian only: the reference's failure path. (C) The reference's silent fallback: contradicts "user asset/config failures remain typed errors" (R6). (D) Check in synthesized templates as an asset: SoundFont-derived data that bypasses the runtime synthesis this story must verify; only reference templates for the fixed-template replay are stored (derived from the pinned CC0 SF2, 55 KB).
- **Limits and known deviations**: The reference renders at 8 kHz natively (FluidSynth aliasing included), the port analyses an alias-free render; the measured template difference is at most 0.039 total variation (tests accept cosine >= 0.99 and variation <= 0.06 per chord, `tests/golden_audio_skf.rs` and `tools/golden/compare.py`). The left channel is used like Partitura's `[::2]`, Reverb Send is 0 like R11. Memory grows with the chord count (0.4 s of audio per chord). A sample rate whose render rate would exceed 192 kHz and pitches outside 0..=127 are `AudioConfig` errors. Partitura's peak normalization is not applied because every row is normalized.
- **How to replace**: edit `synthesize_templates` only (its contract is the doc comment), keep the 8 kHz default working, then re-run `tests/golden_audio_skf.rs` and the audio benchmark row `audio-skf`; the report's parity against the pinned reference decides.

## R13 - CQT numerics, resampler and tolerance

- **Decision**: `cqt` is a targeted port of librosa's recursive `cqt` (`src/features/cqt.rs`): per octave one sparse frequency-domain kernel (Hann-windowed phasors normalized by `norm`, spectral mass sparsified to 99 %, coefficients rounded to `float32` like the reference), the signal halved in rate between octaves, centered frames, response scaled by `1 / sqrt(filter length)`, first and last frame dropped. Every value is computed in `f64`. The `soxr_hq` decimator of `librosa.resample` is replaced by a Kaiser-windowed sinc fitted to its measured response (half length 194, window half-width 194.5, beta 13.040074, cutoff 0.2392179565 cycles per input sample, delay 0, zero-extended edges, gain sqrt(2) from librosa's `scale`). The contract's cqt feature limit gains a frame-maximum term, `|a-b| <= 1e-5 + 1e-5*|ref| + 1e-5*max(|ref frame|)`: a reviewed design change that the maintainer approved on 2026-11-05 after this evidence. Kernel coefficients use the same form with their row maximum (see the known deviations) and the decimation stage keeps the strict per-element limit.
- **Rationale**: The strict limit cannot be met by any implementation that is not bit-identical to the reference. Probes in the locked environment (librosa 1.0.0, soxr 1.1.0 = libsoxr 0.1.3-14-ga66f3ee, SciPy 1.18.1, NumPy 2.5.4): librosa's own `float64` evaluation of the same algorithm already misses its `float32` output by 3 to 18 times the strict limit on pure tones (14.7 times for a chord at hop 735, which needs no resampling at all); `soxr_hq` leaves rounding noise of about 3.3e-8 rms per sample that the long low-octave filters amplify about 8000-fold; an exact-math port deviates from the reference by at most 8e-7 of the largest bin of a frame (-122 dB), which is a ratio of at most 0.07 against the amended limit on typical signals and 0.65 on the worst probe (digital silence followed by a tone). Rebuilding `soxr` bit for bit is not feasible: plain `float32` FIR implementations of its measured taps reproduce only 5 to 14 % of the output bits, the rest is libsoxr's `float32` FFT and SIMD summation order (LGPL C code). The decimator itself is exact to `float32` precision: the fitted taps differ from the measured ones by at most 1.7e-8 (rms 3e-9). Follower impact: the reference's own Arzt (226 steps) and Dixon (379) with `processor=cqt` follow identical paths (maximum difference 0 beat) when its resampler is replaced by the fitted decimator.
- **Alternatives considered**: (A) Keep the strict limit and pause C06, the contract's default for an unreachable limit: no port that is not bit-identical can pass, and C07 and C08 reuse this transform. (B) Bit-exact `soxr`: see above. (C) libsoxr through FFI (`soxr`, `libsoxr-sys`): C bindings, breaks the pure-Rust and WASM builds the plan requires and only removes the resampler's share of the noise. (D) Maintained pure-Rust CQT crates, surveyed 2026-11-05: `cqt-rs` 0.2.1 (MIT, MSRV 1.88, rayon by default) has its own kernel grid and amplitude scaling and an 80 dB Kaiser half-band decimator, and its multi-rate output agrees with its own single-FFT engine within 1 % of a frame's peak; `dasp-rs` 0.6.0 (MIT, MSRV 1.85) runs a full-rate wavelet analysis that its documentation calls not a drop-in replica of librosa's recursive transform (2.54 % relative L2 on tones, 11.3 % in boundary frames); `spectrograms`, `qdft` and `cicuetea` compute other transforms (time-domain correlation with capped kernels, a sliding DFT, an invertible NSGT). None comes within `1e-5` of `librosa.cqt`, so the WASM builds were not attempted. (E) Another reference library (nnAudio, essentia): not the pinned reference. (F) Raise the constants for every processor: rejected by R10; the added term is specific to cqt and relative to the frame.
- **Limits and known deviations**: The decimator is a fit, not a port: against the recorded `soxr` outputs it deviates by at most 9.5e-7 absolute (2.4e-7 in the default case), far inside the strict `1e-5` stage limit. Early downsampling by 4 or 8, which the reference applies above about 70 kHz when the hop is a multiple of 512, is rejected with an `AudioConfig` error: a fit of those chains differed from `soxr` by about 3e-3 over the first 100 outputs (start-up transient); every supported configuration decimates by 2 at most. The kernel row-maximum term goes beyond the approved scope, which named the features: the reference builds its kernels in `complex64` (a `float32` FFT of `float32` filters, coefficients up to thousands) and its rounding noise of about 1e-7 of the row maximum exceeds the absolute `1e-5`; the term only judges an intermediate stage, the features carry the approved limit. The stream adapter gives each call two hops (the cache is one hop) and the first call's output is dropped, so every stream row is an independent transform; there is no state and `reset` is a no-op. A score shorter than two hops is an `AudioConfig` error. `norm` and `n_fft` are no options because the facade does not forward them.
- **How to replace**: edit `halve_rate` (decimator) or the kernel construction in `src/features/cqt.rs`, regenerate the goldens with `tools/golden/generate_audio.py --cqt-only`, run `cargo test --test golden_audio_processors cqt` and the audio benchmark row `audio-cqt`; the limits above decide.
